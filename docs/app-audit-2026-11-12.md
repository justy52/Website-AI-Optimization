# Virelantic app audit — 2026-11-12

Read-only review of `main` at `9749798` (code, live site walk-through). Four areas: automation, user experience, reliability, security. Items marked **(checked)** were re-verified directly in the code after the review; the rest come from a single reading and should be confirmed when picked up.

## Verdict

- The audit engine, tenant isolation, payment reconciliation and SSRF protection are well built.
- Almost none of the service is delivered by AI. One code path can call a language model; it is off by default and its output is never applied to a client's site.
- The owner cannot see failures, is not told about new enquiries, and cannot reset a forgotten password.
- The signed-in app is written in the builder's vocabulary, not the owner's.

## Later / housekeeping

- Role checks missing on lead, client, website, audit-finalize and opportunity mutations **(checked: 0 in `revenue.ts` and `opportunities.ts`)**; latent because no invite flow exists. Add before any second user.
- Sign-up has no email verification and there is no two-factor option (`src/auth/enrollment.ts:34`).
- `TIMED_OUT` is never written; stuck `RUNNING` agent/monitoring/visibility runs have no timeout **(checked)**; a stuck visibility run blocks the workspace.
- No way to delete a customer's data on request (delete-blocking triggers, 73 restrict foreign keys); export caps at 1,000 rows per entity.
- No CI; ~100 database tests skipped by default; e2e defaults to the old `optiq-qa` host.
- Stripe calls made inside open database transactions (`src/server/service-payments.ts:107-206`); audit double-submit race.
- Audit list: per-row subquery on `activity_events` with no matching index, no pagination.
- Stale and risky one-off scripts (`scripts/rotate-closed-intake.mjs`, `setup-rls-test-role.mjs`); 169 leftover "optiq" names; README and env docs out of date; unused dependencies.
- Smaller security items: env detection falls back to "local" with hard-coded secrets off Vercel; unlimited workspace creation; non-constant-time cron secret compare on five routes; IPv6 transition ranges and ports in the SSRF guard; commit SHA on `/api/health`.

## Found sound

Tenant scoping and row-level security, QA route gating, cron authentication (fails closed), Stripe webhook verification and idempotency, Search Console OAuth, report download escaping, SSRF core (DNS pinning, redirect re-validation), paid-AI cost reservation, typecheck and lint clean.

## Not confirmed

Whether removing the five cron entries was deliberate; production env values (`AGENT_PROVIDER`, emergency stop, budgets); Neon snapshot state; Stripe receipt emails; legal sufficiency of the terms and privacy pages; real-world false-reject rate of the claim guard.
