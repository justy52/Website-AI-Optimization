CLIENT INTAKE, LAUNCH & CLOSEOUT CHECKLISTS

CLIENT INTAKE CHECKLIST

AI-FIRST OPERATING PRINCIPLE -> AUTHORITATIVE UPDATE

The business is intentionally designed around AI-agent-assisted fulfillment. AI agents perform the majority of repeatable collection, monitoring, analysis, drafting, prioritization, documentation, reporting, and safe internal execution. Human time is reserved for strategy, client relationships, judgment, quality control, and approval of consequential actions.

Agent permission levels:
1. OBSERVE -> read, crawl, monitor, measure, compare, and report. May run automatically.
2. PREPARE -> draft content, recommendations, schema, metadata, code changes, reports, tasks, and client communications. Output remains a draft until the applicable approval policy is satisfied.
3. EXECUTE -> perform only explicitly allowlisted, low-risk, reversible actions. Live-site publishing, destructive changes, contractual commitments, pricing changes, client-facing sends, and other consequential actions require human approval until a later policy explicitly permits otherwise.

Every material agent action must be tenant-scoped, logged, attributable to an agent/run, evidence-backed where factual claims are made, bounded by cost/time limits, and recoverable or safely retryable.


CHECKLIST UPDATE

Every client launch must also configure:
- Approved agent permission level for the workspace/client.
- Website crawl authorization and scope.
- Connected analytics/search accounts when available.
- Baseline website, SEO, local-search, conversion, and AI-visibility snapshots.
- Approved monitoring cadence.
- Approval contacts and escalation rules.
- Safe execution allowlist, initially empty unless explicitly approved.
- Agent cost/usage ceiling.
- Rollback path for any future executable website action.


Before production begins:  
-> Confirm signed agreement/scope.  
-> Confirm required initial payment.  
-> Identify primary client contact and decision-maker.  
-> Confirm business name, website URL, phone, email, service area, and primary services.  
-> Confirm the primary action the website should generate: call, form submission, booking, purchase, quote request, visit, or other.  
-> Confirm current marketing channels.  
-> Confirm known website problems and client priorities.  
-> Confirm who currently manages the website.  
-> Confirm whether another agency/developer has active access or responsibility.  
-> Collect approved brand assets if needed.  
-> Collect approved copy/content if needed.  
-> Collect required access using delegated/user access whenever available.  
-> Confirm CMS access.  
-> Confirm hosting access if required.  
-> Confirm domain/DNS access if required.  
-> Confirm Google Analytics access if available.  
-> Confirm Search Console access if available.  
-> Confirm Google Business Profile access if relevant.  
-> Confirm Tag Manager access if relevant.  
-> Confirm form/email platform access if relevant.  
-> Document access method without storing exposed passwords in project notes.  
-> Create client project folder.  
-> Save agreement, proposal, audit, and relevant correspondence.

PROJECT LAUNCH CHECKLIST

Before making changes:  
-> Confirm project scope again.  
-> List all in-scope deliverables.  
-> List major exclusions or deferred items.  
-> Confirm communication method and expected review process.  
-> Confirm backup exists or create a current backup.  
-> Verify rollback/restore method.  
-> Determine whether staging can be used.  
-> Capture baseline screenshots of major pages.  
-> Record baseline performance/page-speed data.  
-> Confirm current analytics is functioning.  
-> Test primary contact forms.  
-> Test click-to-call and email links.  
-> Test navigation and mobile menu.  
-> Record obvious pre-existing errors.  
-> Confirm current indexing/noindex settings.  
-> Confirm HTTPS/security basics.  
-> Create change log.  
-> Prioritize work by impact and risk.

IMPLEMENTATION CHECKLIST

For each meaningful change:  
-> Record the page/system being changed.  
-> Record the issue being addressed.  
-> Record the business reason for the change.  
-> Implement the smallest safe solution.  
-> Test the affected page immediately.  
-> Check mobile impact.  
-> Check desktop impact.  
-> Confirm forms/CTAs still work where affected.  
-> Capture before/after evidence when useful.  
-> Add out-of-scope discoveries to a separate future-work list.

FINAL QA CHECKLIST

Before presenting the work to the client:  
-> Homepage reviewed on desktop.  
-> Homepage reviewed on mobile.  
-> Major service/product pages reviewed.  
-> Contact page reviewed.  
-> Navigation tested.  
-> Mobile menu tested.  
-> All primary CTA buttons tested.  
-> Forms submitted successfully.  
-> Phone links tested.  
-> Email links tested.  
-> Broken-link spot check completed.  
-> Redirect spot check completed.  
-> Important page titles/headings reviewed.  
-> No accidental noindex settings introduced.  
-> Sitemap/indexing configuration reviewed where relevant.  
-> Analytics/tracking verified.  
-> Performance retested.  
-> Major visual regressions checked.  
-> Backup/rollback path still confirmed.  
-> Change log is current.

CLIENT REVIEW CHECKLIST

Before or during review:  
-> Prepare concise summary of completed work.  
-> Show the major problems originally identified.  
-> Show what was changed.  
-> Explain why each major change matters in business terms.  
-> Include before/after measurements where meaningful.  
-> Separate completed work from future recommendations.  
-> Identify anything blocked by client access/content/approval.  
-> Request one consolidated feedback list.  
-> Classify requested changes as in-scope or out-of-scope.  
-> Obtain approval for any additional paid work before starting it.

PROJECT CLOSEOUT CHECKLIST

Before marking the project complete:  
-> Complete approved final revisions.  
-> Run final QA after revisions.  
-> Confirm live website is functioning normally.  
-> Confirm forms and lead paths work.  
-> Confirm analytics/tracking remains active.  
-> Save final screenshots and measurements.  
-> Complete final change log.  
-> Prepare final optimization report.  
-> Record remaining recommendations by priority.  
-> Confirm final invoice/payment status.  
-> Remove unnecessary account access.  
-> Keep only access required for approved ongoing service.  
-> Save final client communications.  
-> Mark project completed or move to ongoing-service status.  
-> Request client review/testimonial when appropriate.  
-> Ask for referrals when the client is satisfied.

ONGOING SUPPORT CHECKLIST

If the client continues into recurring service:  
-> Define exact monthly/quarterly scope.  
-> Define included hours/tasks or deliverables.  
-> Define what is not included.  
-> Define response expectations.  
-> Define reporting cadence.  
-> Confirm recurring billing.  
-> Establish recurring performance/SEO/analytics review.  
-> Track new requests separately from included maintenance.  
-> Review whether the retainer still provides clear value at renewal.
