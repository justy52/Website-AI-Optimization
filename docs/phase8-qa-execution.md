# Phase 8 governed QA execution

The only execution action is qa.metadata.apply-v1.0, available through the dedicated QA kernel. No customer adapter, arbitrary HTTP write, CMS credential, Google write or email action exists. EXTERNAL_EXECUTE_ENABLED remains false. The general agent permission boundary still rejects EXECUTE; only this explicit QA path admits execute.qa_metadata.v1 after all gates.

APP_ENV=qa, canonical BETTER_AUTH_URL=https://optiq-qa.vercel.app, QA_EXECUTE_ENABLED=true, both workspace flags (qa.execute and qa.metadata.apply), current OWNER/ADMIN membership, exact enabled versioned agent/tool, exact immutable approved action, LOW fixture-only risk, unexpired bounded run, target binding and precondition must all pass. Workspace flags default disabled. Queued work rechecks them immediately before mutation under the workspace lock. Vercel's Production target for optiq-qa is still APP_ENV=qa; an actual APP_ENV=production or local instance is blocked even if the flag is true.

One fixture is allowed per disposable QA workspace, preserving existing website-domain uniqueness. Each fixture belongs to a synthetic Growth client/site with fixed public QA facts. Public GET exposes only escaped, bounded title/description and fixed harmless text; it offers no public write method and is unavailable outside QA. Target URLs are constructed from fixed canonical QA origin plus exact workspace/fixture UUIDs. No arbitrary HTML, scripts or URLs are accepted. TITLE_MISMATCH is an explicit QA delivery-fault scenario: after APPLY, the public route serves a fixed incorrect title. The ordinary safe-fetch verifier detects it; after rollback, normal delivery resumes. There is no verifier bypass or synthetic pass.

An approved implementation package binds the artifact, version and original human artifact approval. A separate execution approval binds exact package hash, artifact version, before/after metadata, fixture revision/hash, target, action/tool versions, risk, rollback policy and verification requirement. Its decision can change once from pending; material fields and history cannot be updated/deleted. New changes require a new execution approval. Artifact approval alone is insufficient.

ExecutionRecord stores exact immutable action, approval, package, agent run, actor/trigger, before/after snapshots, idempotency fingerprint, change ID, timestamps, verification run/evidence and safe errors. Unique workspace/idempotency keys plus database workspace/record/fixture locks serialize duplicate requests and concurrent workflow retries. The fixture trigger only accepts exact approved values from a matching RUNNING record with the expected prior revision/metadata. One apply action advances one fixture revision. Execution records permit controlled transitions while active; terminal rows and all history reject ordinary deletion or rewriting.

The write finishes SUCCEEDED before independent verification. verification-v1.1 remains OBSERVE and uses the existing public safe-fetch and parsed metadata comparison. Expected values come from the immutable approval, not a self-reported write outcome. FAILED/UNAVAILABLE/WARNING never become verified success. Verification evidence stores expected/observed comparisons, public content hash, time, method and limitations.

Only deterministic VERIFICATION_FAILED causes automatic QA rollback. WARNING/UNAVAILABLE retain successful-write status with a separate non-success verification result for human review. OWNER/ADMIN may request manual rollback. Rollback is its own retained child ExecutionRecord, restores the original before snapshot only when the fixture still matches the original post snapshot, and is independently verified. The original failed/succeeded record is never rewritten. A paused platform/workspace also blocks rollback; enable the reviewed switch before a new authorized rollback retry.

QA execution is sandbox proof, not contracted customer fulfillment. It does not create manual minutes or automatically award Monthly Cycle completion. All Phase 5 accounting remains authoritative. Live AI is unnecessary and remains disabled. Execution and independent OBSERVE runs use persisted versioned definitions, normal budgets and tool-call audits; fetched content has no authority over action data, permissions, tools, rollback or tenancy.

Migration 0015 adds three tenant tables with composite tenant FKs, RLS and FORCE RLS; it adds the immutable versioned QA agent definition and controlled-transition/retention triggers. Migration 0014 retains Phase 7 implementation packages and verification attempts against ordinary UPDATE/DELETE. Future privileged workspace purge requires a separately reviewed path.
