WEBSITE OPTIMIZATION SERVICE DELIVERY SOP

PURPOSE  

AI-FIRST OPERATING PRINCIPLE -> AUTHORITATIVE UPDATE

The business is intentionally designed around AI-agent-assisted fulfillment. AI agents perform the majority of repeatable collection, monitoring, analysis, drafting, prioritization, documentation, reporting, and safe internal execution. Human time is reserved for strategy, client relationships, judgment, quality control, and approval of consequential actions.

Agent permission levels:
1. OBSERVE -> read, crawl, monitor, measure, compare, and report. May run automatically.
2. PREPARE -> draft content, recommendations, schema, metadata, code changes, reports, tasks, and client communications. Output remains a draft until the applicable approval policy is satisfied.
3. EXECUTE -> perform only explicitly allowlisted, low-risk, reversible actions. Live-site publishing, destructive changes, contractual commitments, pricing changes, client-facing sends, and other consequential actions require human approval until a later policy explicitly permits otherwise.

Every material agent action must be tenant-scoped, logged, attributable to an agent/run, evidence-backed where factual claims are made, bounded by cost/time limits, and recoverable or safely retryable.


AI-FIRST FULFILLMENT TARGETS

The delivery system is designed around these steady-state human fulfillment targets after tooling matures:
- Essentials: approximately 45-60 minutes per client per month.
- Growth: approximately 1.25-2 hours per client per month; operating target about 1.5 hours.
- Pro: approximately 2.5-3.5 hours per client per month; operating target about 3 hours.

Agents should handle recurring website-health monitoring, Search Console analysis, keyword and competitor monitoring, AI-visibility testing, content opportunity discovery, first drafts, existing-page optimization drafts, internal-link recommendations, schema drafts, monthly reporting, and plain-language client summaries. Human review remains required for consequential live changes, final client-facing strategy, and final publishing decisions unless an explicit allowlist says otherwise.

This SOP defines the repeatable delivery process for website Optimization Launch projects. It is designed for small-business websites where the goal is to improve usability, performance, conversions, search visibility, and overall professionalism without overcomplicating the engagement.

1. PROJECT START  
Confirm before work begins:  
- Signed scope/agreement  
- Initial payment received  
- Primary client contact identified  
- Required access granted  
- Project folder created  
- Audit and proposal saved  
- Communication channel established

2. PRE-WORK SAFETY CHECK  
Before editing the live website:  
- Confirm current backup exists or create one.  
- Confirm how to restore/rollback.  
- Determine whether staging is available.  
- Record current CMS/theme/plugin/version information where relevant.  
- Capture screenshots of major pages.  
- Record baseline performance metrics.  
- Confirm forms, phone links, and major conversion actions currently work.

3. BASELINE REVIEW  
Evaluate the website across six core areas.

A. Technical Health  
Check for broken pages, broken links, redirect problems, HTTPS/security issues, indexing problems, duplicate content signals, sitemap/robots issues, plugin/theme conflicts, and obvious technical errors.

B. Performance  
Review load speed, Core Web Vitals, oversized images, render-blocking resources, unused scripts/styles, caching, CDN usage, font loading, third-party scripts, and mobile performance.

C. User Experience  
Review mobile layout, navigation, readability, page hierarchy, forms, contact methods, trust signals, accessibility basics, confusing interactions, and friction in important customer journeys.

D. Conversion  
Identify the primary action each major page should generate. Review calls to action, offer clarity, contact placement, quote/request flows, social proof, guarantees, differentiators, and unnecessary steps.

E. Search / Local SEO  
Review titles, meta descriptions, headings, page targeting, internal linking, location/service relevance, structured data opportunities, Google Business Profile alignment, indexation, and Search Console signals when available.

F. Analytics & Measurement  
Confirm what can currently be measured. Review analytics, Search Console, Tag Manager, conversion events, form tracking, phone-click tracking, and other meaningful lead actions.

4. PRIORITIZATION  
Do not work from a random list of issues. Rank work using:  
- Business impact  
- User impact  
- Search impact  
- Technical risk  
- Effort required  
- Dependency on other changes

Use this sequence by default:  
1. Broken or risky items  
2. Lead-blocking usability issues  
3. Speed/performance  
4. Conversion improvements  
5. Technical SEO  
6. On-page/content structure  
7. Tracking/measurement  
8. Visual polish

5. IMPLEMENTATION  
For each change:  
- Record what is being changed.  
- Note the reason/business objective.  
- Make the smallest safe change that solves the problem.  
- Test immediately after implementation.  
- Preserve screenshots or before/after evidence when useful.  
- Log anything discovered that is outside scope.

Avoid making broad, unrelated site changes just because access is available.

6. PERFORMANCE OPTIMIZATION  
Typical work may include:  
- Image resizing/compression/modern formats  
- Lazy loading  
- Removing unnecessary scripts/plugins  
- Caching improvements  
- CDN configuration  
- Font optimization  
- CSS/JavaScript reduction where safe  
- Reducing third-party overhead  
- Fixing layout shift sources  
- Improving server response or hosting configuration when within scope

Always verify functionality after performance changes.

7. CONVERSION OPTIMIZATION  
Typical work may include:  
- Stronger page headlines  
- Clearer service/offer language  
- More visible calls to action  
- Simplified forms  
- Click-to-call improvements  
- Better contact placement  
- Trust badges/testimonials/reviews  
- Improved service-area messaging  
- Better quote/booking flow

Optimization should fit the client's real sales process rather than forcing generic marketing tactics.

8. SEO OPTIMIZATION  
Typical work may include:  
- Unique page titles/descriptions  
- Correct heading hierarchy  
- Internal linking  
- Service/location page refinement  
- Sitemap/indexing cleanup  
- Canonical/redirect corrections  
- Image alt text where meaningful  
- Schema/structured data where appropriate  
- Search Console issue remediation  
- Content improvements based on user intent

Never guarantee search rankings.

9. QA AFTER CHANGES  
Run a structured QA pass:  
- Homepage  
- Top service/product pages  
- Contact page  
- Lead forms  
- Primary CTA buttons  
- Phone and email links  
- Mobile menu/navigation  
- Desktop navigation  
- Common mobile viewport  
- At least one modern Chromium browser  
- Additional browser/device checks as needed  
- 404/broken-link spot check  
- Redirect spot check  
- Analytics/events  
- Search indexing settings

10. MEASUREMENT  
Re-run relevant baseline tests and record:  
- Page-speed changes  
- Core Web Vitals where measurable  
- Page-size/request reductions if relevant  
- Fixed errors  
- Conversion-flow changes  
- Tracking improvements  
- Search/technical fixes

Not every project will show immediate traffic or lead growth. Separate technical improvements completed now from business results that require time and traffic to measure.

11. CLIENT REVIEW  
Prepare a concise review containing:  
- Original issue  
- Change made  
- Why it matters  
- Before/after evidence when available  
- Remaining recommendations

Ask the client to consolidate feedback into one review cycle whenever the agreement allows.

12. CHANGE REQUESTS  
A request is outside scope when it adds a new page, feature, integration, content project, redesign, campaign, or other meaningful deliverable not included in the agreement.

For out-of-scope requests:  
- Document the request.  
- Explain that it is additional work.  
- Price it separately or move it to a future phase.  
- Obtain approval before implementation.

13. CLOSEOUT  
Before closing the project:  
- Complete approved revisions.  
- Perform final QA.  
- Confirm backups/restore path.  
- Verify analytics/tracking.  
- Deliver final optimization summary.  
- Provide future recommendations.  
- Confirm final invoice/payment.  
- Remove unnecessary access or leave approved ongoing access only.  
- Request testimonial/review/referral when appropriate.

14. PROJECT RECORD  
Each completed client folder should contain, at minimum:  
- Agreement/scope  
- Audit  
- Access notes without exposed passwords  
- Baseline report  
- Change log  
- Before/after evidence  
- QA checklist  
- Final report  
- Invoices/payment record  
- Future opportunities/retainer notes

DEFINITION OF DONE  
A project is complete when the contracted work is implemented, tested, documented, reviewed with the client, paid according to the agreement, and either formally closed or transitioned into an ongoing service plan.
